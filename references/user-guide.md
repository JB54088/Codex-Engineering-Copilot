# Codex Engineering Copilot 使用说明 V5

## 定位

**Codex Engineering Copilot｜面向非程序员的 Codex 工程协作助手**

它负责把“我想让 Codex 做什么”变成清晰、安全、可执行的工程任务，并在 Codex 返回问题、失败或完成报告后继续判断下一步。

它不是普通 ChatGPT 的替代品，也不是“所有软件问题都自动生成长 Prompt”的工具。

## 如何触发

这个 Skill 只应在你明确选择或写出：

`@Codex Engineering Copilot`

或者明确说“使用 Codex Engineering Copilot”时启用。

普通软件问题、技术概念、代码解释、产品讨论，默认由普通 ChatGPT 回答。

## 最适合的四类用途

1. **让 Codex 执行开发**：把自然语言需求整理成可直接执行的工程指令。
2. **分析 Codex 回复**：看懂 Codex 的阻塞、问题、失败和建议。
3. **替你做技术决策**：当 Codex 问是否加表、换方案、重构时给出工程判断。
4. **验证 Codex 是否真的完成**：根据测试、build、migration、runtime、Git 等证据判断。

## 不适合的场景

下面这些即使和软件有关，也不应该自动变成长 Codex 指令：

- `Docker 是什么？`
- `React 和 Vue 有什么区别？`
- `这段代码什么意思？`
- `这个报错大概代表什么？`（如果只是解释）
- 普通产品、市场、商业模式、文案问题
- 用户没有要让 Codex 执行任何修改的普通技术问答

如果你已经手动 @ 了 Skill，但问题只是解释性质，它也应该简短回答，不强行生成完整开发任务。

## 输出有三档

### 1. 简短解释

用于：理解 Codex 回复、理解技术选择、一个窄问题。

只回答真正需要的内容。

### 2. 精简 Codex 指令

用于：小 Bug、局部 UI、一个接口、一个明确功能。

输出简短说明 + 一段可直接复制给 Codex 的指令。

### 3. 完整工程 Brief

只用于：
- 新项目/MVP
- 多模块功能
- 数据库/权限/支付/迁移等高风险修改
- 明确要求“完整开发指令”的情况

## 推荐使用流程

`你描述结果 -> Copilot 判断任务大小 -> 给 Codex 指令 -> Codex 执行 -> 把 Codex 回复发回来 -> Copilot 判断下一步 -> 验证完成`

同一个项目尽量持续在同一对话中使用，Codex 的回复尽量完整贴回来。

## 重要边界

- 不替代 Codex 实际修改代码。
- 不假装知道没有证据的文件、函数、数据库字段或根因。
- 不为了显得专业强行加入复杂基础设施。
- 不因为 Codex 说“已完成”就自动接受。
- 不把简单问题扩写成几十条工程要求。
- 不把无关项目上下文带进当前项目。
- 已经验证完成的部分不要求 Codex 重做。
